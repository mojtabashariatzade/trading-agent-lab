## Changes in this PR

- M1 execution now censors unobserved initial/interior minutes before determining an exit. A missing interval is not the same thing as a price gap between observed bars. A trade already resolved before a later gap stays resolved.
- Opening quotes resolve a known stop/target before applying conservative SL-first to an unknown intraminute path. A target reached at the open is not converted into a later stop.
- TP is explicitly modeled as a resting limit order: no adverse market slippage below/above its limit. Entry, SL and TIMEOUT retain adverse slippage and commissions. This is an execution-model assumption, not proof of a broker fill.
- M1 inputs reject crossed bid/ask extrema and non-minute-aligned entries rather than silently simulating missing seconds.
- The account rejects a new entry inside a previous trade's execution interval even when the previous batch call has returned.
- Entry commission is deducted for censored/open trades; final P&L remains unknown.
- Non-finite arithmetic is rejected. Execution model identifier: `m1-2.0.0`.
- Manifest generation processes timestamps once, without retaining the entire timestamp list. Memory is O(number of reported gaps), plus the fixed payload hashing buffer.

Old and new execution outcomes are intentionally not equivalent for the corrected edge cases. Previously generated labels/results must not be mixed with the new execution model. No old performance result is promoted by this PR.

## Remaining correctness gates -- not fixed by this PR

1. `TournamentRunner._data_ready` currently depends on future `m1_bars` being non-empty. Entry eligibility must depend only on information available at decision/entry; missing future data must censor an already-entered trade, not erase its entry. Add future-tail deletion invariance tests.
2. M1 timeout currently uses the previous bar close at its end. That is an explicit proxy, not necessarily the first executable quote at the timeout boundary. Add a quote-based timeout path or record this limitation before using real data.
3. Quote contracts need a consistent `event_time`/`available_at`/fill-ready timeline. The synthetic runner equates decision time and entry time. Add latency and staleness tests instead of calling this broker-realistic.
4. Session breakout accepts a nonempty partial opening range; verify complete scheduled range coverage. Closed-bar contracts should derive gap continuity from timestamps, not trust a caller-supplied boolean. Normalize and validate tick counts before coercion.
5. `EconomicRelease.pre_release_forecast` has no independently recorded forecast-observation timestamp. Add field-level provenance and point-in-time checks. Hour/minute precision must use conservative availability bounds; day/unknown rejection alone is not enough.
6. Manifest timestamps are supplied separately from payload bytes. A matching checksum does not prove those timestamps were parsed from those bytes. Implement verified format adapters, immutable payload snapshots and archive permission/provenance gates.
7. Mark-to-market equity, cash/margin, risk sizing, late fills and rollover require acceptance tests. Current batch account cash is not a full event-sourced portfolio ledger.
8. Add mutation/adversarial tests and actual numeric expected values (ATR recurrence, source revisions, sign symmetry). A high unit-test count alone is not independent validation.

## Fifteen-family tournament: retained, with stricter selection

Issue #38 remains the product target: variants compete within a family; validated champions compete across families; the Decision Core consumes eligible specialist outputs and can PASS.

- Use one versioned strategy registry. The family list in PROJECT_CONTRACT.md and issue #38 is not identical; reconcile it explicitly rather than silently redefining the product.
- Distinguish family, variant, execution horizon and context filters. EMA, momentum and multi-timeframe filters are not automatically independent information sources.
- Perform within-family tuning AND cross-family selection inside each permitted temporal training/development fold. Use outer windows only to evaluate the frozen selection process. A globally selected champion cannot be retroactively treated as out-of-sample.
- Keep signal, native-system and Core competitions separate. The current fixture defaults (60 minutes and fixed 0.30/0.60 exits) are not the product's ATR14/3R/240-minute signal contract.
- Track every search trial and the search budget per family. Check out-of-sample uncertainty, cost stress, correlation of losses and incremental contribution; do not force a winner from every family.
- Macro/news experts remain INELIGIBLE until point-in-time source coverage and licensing are verified. No fabricated consensus values or revisions.
- Start with a deterministic selection baseline. A trained gate must demonstrate incremental value in matched out-of-sample ablations before becoming the default.

## Performance plan -- proposals, not measured improvements yet

- Archive and parse raw data once; use immutable partitioned datasets. Cache causal feature arrays with keys containing data hash, feature version, parameters and training cutoff.
- Stop reparsing the full history and recomputing four full EMA passes at every decision. Use a validated streaming state or precomputed causal arrays, with batch-versus-stream equivalence tests.
- Use index-based slices rather than copying every historical prefix into each opportunity. Keep replay state chronological.
- Parallelize independent family/fold experiments with a bounded worker pool; keep a single writer for portfolio/merge state. Use content-addressed experiment IDs to resume without duplicate work.
- Do not add microservices, Redis, Kubernetes or a larger model before a measured bottleneck requires them. Research-only tasks and strategy-card work can proceed while data access is being verified; actual ranking cannot.
